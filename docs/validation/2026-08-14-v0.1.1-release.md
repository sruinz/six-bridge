# SIX Bridge v0.1.1 릴리스 검증

검증일은 2026-08-15이며, 대상 제품 버전은 `0.1.1`, Android
`versionCode`는 `2`, macOS native package 버전은 `1.0.1`이다.

## 자동 검증

- `scripts/release-contract.test.sh`, release key 초기화 계약,
  `release-lib`, `prepare-release`, `publish-release-tag`, desktop/Android
  distribution 회귀가 통과했다.
- `scripts/verify.sh`가 JVM, Android, Node, Fold7 host fixture와 release
  pipeline 회귀를 포함해 통과했다.
- 최종 Android 변경 뒤 JDK 17 Android unit suite와 `lintDebug`가
  통과했다. SecureDirectoryStream을 요구하는
  `OnDeviceInputServiceTest`와 `DefaultConversionRuntimeTest`는 JDK 26에서
  별도로 통과했다.
- `ManagerViewModelTest` 232개, `ManagerAppTest` 48개,
  `ManualApkExportInstrumentedTest` 2개가 모두 통과했다.

## Fold7 acceptance

검증 기기는 SM-F966N이며 실제 Samsung Internet APK는 수정하지 않았다.
관리자 앱은 데이터 삭제나 uninstall 없이 release-signed APK로 update했고,
`versionName=0.1.1`, `versionCode=2`를 확인했다.

다음 lifecycle 계측을 실제 기기에서 각각 통과했다.

| 경로 | 결과 |
|---|---|
| markerless ZIP `CreateNew` | BUNDLE_READY 뒤 ACTIVE target 1개 |
| zero-adapter desktop SixDraft | passthrough bundle 패키징 성공 |
| package 실패 뒤 같은 job 재시도 | identity와 target 각 1개 유지 |
| 자체 서명 wrapper APK | 설치 성공, Samsung Internet discovery/provider 확인 |

ignored evidence는
`.local/evidence/20260815-v0.1.1-fold7.UzefVp/`에 보존했다.

## 실사용 중 발견한 추가 결함과 교정

첫 candidate 뒤 실제 확장 ZIP을 시험하며 다음 두 결함을 발견했다.

1. MV2 manifest의 `manifest_version`만 3으로 바꾼 입력은
   `options_ui.chrome_style` 때문에 Samsung Internet에서 설치 완료되지
   않았다. 브라우저의 정확한 오류는
   `The chrome_style option cannot be used with manifest version 3.`였다.
   `aab8eadc`는 이 조합을 패키징 전에 차단하고 원인을 표시한다.
2. 이전 manual APK export 상태가 새 ZIP 또는 `.six` review에 전역으로
   노출되어, 실제 저장 전에도 `APK를 저장했습니다.`가 표시될 수 있었다.
   `8fac50cc`는 export 상태를 exact review token에 결속하고 새 작업 또는
   복원된 결과의 export 전에 이전 소유 상태를 정리한다.

두 번째 수정 뒤 Fold7에서 다음 실제 저장을 확인했다.

| 입력 | 저장된 APK 크기 | SHA-256 |
|---|---:|---|
| 기존 setube 결과 | 2,318,606 bytes | `f4afdf5ec180be677a14192e1d2d25786c81fba0c87be1dce2d4b9fa1c7ca55b` |
| `AI-to-Pinry-fixed.zip` | 2,298,126 bytes | `be1adc14bd6fc0026e97d199a1baa0c5113718476ca48a743c422c623cc77f59` |
| 기존 `AI to Pinry` `.six` | 2,298,126 bytes | `290ddfe8c2f4ba15955df36017673ce975888b74f07333a9d368617bd1617704` |

세 경로 모두 시스템 파일 앱에서 저장을 확정한 뒤에만 완료 문구가
나타났다. `.six` 경로의 실제 파일 해시는 review에 표시된 값과 같았고,
APK v3 서명 검증과 wrapper signer
`be2a4c6c27daa935e34f2ccadeee2d63b018aff7a1ffaca4dc442b0ea7eef187`
일치도 확인했다.

최종 관리자 release APK는 SHA-256
`ad4ddbf0ed77d01743b4b8aa50f46c5baa7d1ffdfc6e7a3b70a9461297e0fca3`이며,
release signer는
`419a3d2f645e6b25411d66a93ec793ab89ed4b32161dec5ed55298715a3da51e`이다.

## 보존·게시 상태

- Samsung Internet APK, 기존 설치 확장 데이터, v0.1.0 tag와 asset은
  변경하지 않았다.
- v0.1.1 tag, remote push, GitHub Release 생성은 아직 시작하지 않았다.
- `f560219a`를 가리키는 첫 v0.1.1 candidate는 최종 수정 두 건을 포함하지
  않으므로 게시 대상에서 제외한다.
- 이 문서가 포함된 최종 private commit에서 candidate를 다시 만들고,
  exact five files, checksum, signer/version, DMG, metadata의 current HEAD
  결속을 모두 재검증한 뒤에만 게시 단계로 넘어간다.
